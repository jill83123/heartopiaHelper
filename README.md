# 心動小鎮助手 (heartopiaHelper)

《Heartopia》的自動化小工具，以畫面比對找出圖示並自動點擊。目前支援：

- **料理**：自動點鍋子、開始烹飪、收料理，可設定要煮的份數。
- **雪雕**：自動點雪花、放置、開始、完成。
- **釣魚**：沒拋竿時自動拋竿，並定時噴香水、放誘魚器、丟維修盒、吃指定食物。
- **採集**：定時採集植物或砍木頭（兩個功能各自獨立，只能擇一使用），砍木頭可定時吃食物。

## 兩種操作模式

| | 前景模式 | 模擬器模式 |
| --- | --- | --- |
| 適用 | PC 版遊戲 | BlueStacks 等模擬器（經 ADB） |
| 視窗 | 遊戲須在最上層，不能被其他視窗蓋住 | 可被其他視窗蓋住，不需要在最上層 |
| 原理 | 截取桌面畫面、模擬滑鼠點擊 | ADB 截圖與點擊 |

「料理」、「雪雕」和「採集」（植物、砍木頭）共用同一個操作模式，這些分頁各有一個「操作模式」下拉選單，改任何一個另一個會跟著變。釣魚的「前景定時」固定走前景模式，「背景定時」固定走模擬器。解析度、ADB 等共用設定在「設定」分頁，分成「前景設定」與「背景設定」兩區。

## 安裝與執行

需要 Windows 與 Python 3.13。

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

## 使用方式

1. 在「設定」分頁確認「前景設定」或「背景設定」（見下方）。
2. 到「料理」、「雪雕」或「採集」分頁選好「操作模式」（共用）：
   - 料理：按「選取範圍」後在畫面上拖曳，框住鍋子、火、手套、計時器等圖示會出現的位置。
   - 雪雕：不用選範圍，直接偵測整個遊戲畫面。
3. 按「開始」；若設定不完整，會跳出視窗列出原因而不會啟動。換了操作模式後，先前框選的泡泡區域要重新選取。按「停止」或設定的停止按鍵（預設 `F8`）可隨時中止。

### 前景模式

- 「遊戲解析度」預設為自動偵測（讀取遊戲視窗大小，需正確填寫遊戲視窗標題）；偵測不準時可手動指定。「介面縮放比例」須和遊戲內設定一致。
- 運行中請讓遊戲保持在最上層。
- 按範圍按鈕框選時，程式會自動把遊戲切到最前面，選完再切回本程式。

### 模擬器模式

1. 在模擬器設定中開啟 ADB（BlueStacks：在設定中開啟「Android 偵錯橋 (ADB)」）。
2. 到「設定」分頁填入「ADB 路徑」（設定頁內有安裝說明）與 ADB 裝置位址。設定頁的「模擬器」選單可一鍵填入常見位址：BlueStacks、雷電為 `127.0.0.1:5555`，MuMu 12 為 `127.0.0.1:16384`，MuMu 6 為 `127.0.0.1:7555`，夜神為 `127.0.0.1:62001`；連不上時請到模擬器的 ADB 設定或多開器確認實際位址。
3. 若要先測試連線，可在專案目錄執行：

   ```powershell
   python -m tools.adb_check adb 127.0.0.1:5555
   ```

   會連線並把畫面存成 `adb_check.png`，不會點擊任何東西。若 `adb` 不在 PATH，請在設定分頁填入「ADB 路徑」。
4. 釣魚的「吃食物」需要輸入中文，程式內附 [ADBKeyBoard](https://github.com/senzhk/ADBKeyBoard)（GPL-2.0，未修改，檔案為 `tools/ADBKeyboard.apk`），第一次吃食物時會自動裝進模擬器，並在輸入前後自動切換輸入法，不需要手動安裝。
5. 模擬器請把解析度設成 1600×900（模板以此為基準）。其他解析度會自動縮放。

### 釣魚

不需要框選範圍。讓角色站在水邊、面向水面並裝備釣竿，在「釣魚」分頁勾選要用的項目後按「開始」。

- **前景定時開關**：釣魚分頁的「前景定時」預設啟用，關閉後按「開始」就不會執行前景定時，可以只跑背景定時；兩邊都沒啟用時無法開始。
- **背景定時（雙開）**：勾選「背景定時（模擬器）」區塊的「啟用」後，按「開始」會同時啟動兩個任務：前景定時（目前的操作模式，通常是前景模式）負責釣魚，背景定時連到設定分頁的模擬器（ADB 路徑與裝置位址和設定分頁共用，背景定時區塊裡的「模擬器連線設定」改的是同一份），所以前景定時必須用前景模式；背景定時在模擬器裡做它自己勾選的項目（選項和前景定時完全一樣：自動拋竿釣魚含香水、誘魚器、維修盒、吃食物，各自有獨立的間隔設定）。誘魚器的效果前景帳號也吃得到，所以若由背景定時放，建議取消前景定時的「放誘魚器」。背景帳號要先站在前景帳號附近的水邊，並完成新手教學；背景日誌顯示在前景日誌下方。
- **自動拋竿釣魚**可以關閉：關閉後不會拋竿，只定時丟維修盒、放誘魚器、吃食物等。
- 自動釣魚時，只有搭配「噴香水」才可以使用（魚會直接上鉤，不需要操作釣竿）。
- 拋竿中背包 (B) 與工具包 (T) 都打不開，所以定時項目到期後，會等魚釣起、竿子收回來才執行。
- **香水**：只看畫面上的圖示，不看計時。開始時先看地圖下方有沒有綠色香水圖示，有就不噴；回到主畫面後圖示連續消失約 3～4.5 秒才補噴（避免閃爍或偶爾認不出來就誤噴；沒有香水效果就不繼續釣魚）。拋竿中看不到圖示，但有香水魚會很快上鉤、回到主畫面就能看到；連續拋竿超過 40 秒都沒釣到魚，會收竿回主畫面確認。若噴了兩次還是看不到圖示，會停止噴香水與釣魚並提示。道具從背包的「釣魚用品」分類取得。
- **誘魚器**：沒有圖示，依設定的間隔（預設 63 秒）放置。沒有魚影就釣不到魚，建議一定要開。
- 為了避免完全定時，每一輪的間隔會隨機多延後，點擊位置與停頓也有小幅隨機。延後上限為間隔的 10%；香水、誘魚器因為有持續時間（2 分鐘、1 分鐘），上限改為「設定的間隔 − 持續時間」，預設香水 123 秒、誘魚器 63 秒，各最多延後 3 秒。
- **無法開始的原因**：料理、雪雕、釣魚按「開始」時若設定不完整，會跳出視窗列出原因，例如「前景定時未設定食物名稱」、「未選取泡泡區域範圍座標」。
- **桌面通知**：香水或誘魚器用完、食物找不到或吃完、噴了香水卻看不到圖示等需要你處理的狀況，除了寫進日誌，也會跳出 Windows 桌面通知（標題會標明是前景定時還是背景定時）；食物剩最後一次而保留不吃時也會通知一次。通知的同時，程式在工作列的圖示也會閃爍，直到你點開視窗（Windows 的「專注輔助／請勿打擾」開著時桌面通知會被吸收，閃爍仍會出現）。
- **背包**：第一次選好「釣魚用品」後，會順便開啟遊戲的「下次開啟背包保持該結果」，之後打開背包就直接在這個清單；要搜尋食物或背包停在其他結果時，會先按「結束篩選」回到完整清單。這個遊戲設定會一直開著，手動打開背包時也會停在上次的結果，可按「結束篩選」取消。
- 遊戲有時會卡住滑鼠、讓視角跟著滑鼠轉動，所以開始時以及每次操作背包、工具包、拋竿前，會先在遊戲畫面上方中間左右鍵各點兩下（僅前景模式）。
- **維修盒**：使用工具包 (T) 最左上、木頭材質的那個。開始後不會馬上丟，要等一個間隔才第一次丟。
- **食物**：有兩種時機：每隔設定的分鐘數（預設 10 分鐘）吃一次；或操作中剛好看得到飽食度（地圖旁邊的體力條）且低於設定的 %（預設 50%）就馬上吃。不會為了看飽食度特地打開背包。定時時間到了，或看到的飽食度高於你設定的 % 時，都不會吃，定時的下一次會往後延一個間隔（完全以你設定的 % 為準）。用名稱在背包搜尋，可指定星級（1～4 星，或不限＝吃第一個）。體力已滿時會略過。需輸入中文；勾選「吃食物」但沒填名稱時，會提示並無法開始。可使用多次的食物（說明裡有「可用次數：2/4」，例如原始風味套餐）可勾選「保留最後一次不吃」：同名同星級的食物每一份各佔一格、各有剩餘次數，剩最後一次的那份會跳過、往下一格找，每一份都只剩最後一次（或找不到）時不吃並通知；採集會直接停止腳本，釣魚則等下個間隔再試。飽食度是用體力條青綠色的比例估算，誤差約 ±2%，超過 100% 時不準。「保留最後一次不吃」會逐格檢查：同名食物每一份各佔一格，某一格只剩最後一次就往下一格找，每一份都只剩最後一次才放棄（釣魚：這次不吃，下個間隔再試；採集：沒有可以吃的食物會通知並停止腳本）。可勾選「不吃 5 星的食物」，星級選「不限」時會跳過 5 星的格子（釣魚、背景定時、植物、木頭都有，預設不勾選）。
- **拋竿鈕**：釣竿有各種造型，鈕裡面的圖案每個人不同。程式在主畫面（看得到背包）時，會把右下角拋竿鈕目前的樣子記下來，之後用你自己的樣子判斷是否正在拋竿；在主畫面要拋竿時，就算比對不到圖也會直接點拋竿鈕的固定位置。
- **設定旁的圖示**：香水、誘魚器、維修盒的設定旁邊有道具圖示，進階的各項目比對閥值旁邊也有模板縮圖（都取自 `templates`），方便辨認。

### 採集

「採集」分頁選擇「採集植物」或「砍木頭」，兩個功能的設定、日誌與開始/停止按鈕各自獨立，同時只能跑一個。不需要框選範圍：讓角色站在採集點或樹前面，設定好後按「開始」。

- **採集次數／砍的次數**（預設 1）：每一輪對著目標按幾次互動鍵（電腦版 F；模擬器點右下角的動作鈕，位置與釣魚的拋竿鈕相同）。
- **定時時間（重生基準）**（預設 120 秒）：植物、木頭多半 2 分鐘重生，以此為基準，每隔這麼久做一輪，開始後馬上做第一輪。
- **操作模式**：與料理、雪雕共用，選前景（遊戲須在最上層，被蓋住時不會按鍵並提示）或背景（模擬器 ADB）。
- **人味**：真人不會剛好在重生那一秒回來，所以每輪實際等待 = 重生基準 + 0.5～4.5 秒的延遲，約八分之一的機率再多分心 4～15 秒；按下前會有隨機的反應時間，連按之間的停頓與按住的時間都有隨機，偶爾還會多停一下。
- **吃食物**（只有砍木頭有，無工具的採集植物不需要）：與釣魚相同，每隔設定的分鐘數吃一次，或畫面上看得到飽食度且低於設定的 % 就吃（不會為了看飽食度特地開背包），需填食物名稱。預設不勾選。**鎖定食物**（預設勾選）：採集幾乎不碰背包的其他東西，所以第一次搜尋食物時會順便開啟遊戲的「下次開啟背包保持該結果」，之後開背包就直接停在這份食物，不用每次重新搜尋；若背包沒停在預期的結果，會自動改回完整搜尋。
- **丟維修盒**：與釣魚相同，每隔設定的分鐘數（預設 15）從工具包丟一次，開始後要等一個間隔才第一次丟。砍木頭預設勾選，採集植物預設不勾選。砍木頭的「間隔」可選「自動計算」（預設）或「手動設定」：選自動時填入斧頭耐久（發展家等級 48 為 200），程式依維修盒每秒回復 3%、持續 17 秒（約回復耐久的 51%），配合每輪砍的次數與定時時間算出間隔（剛好用完一個維修盒的回復量，丟下去剛好回滿、不浪費），例如耐久 200、每輪砍 1 次、2 分鐘一輪，約每 204 分鐘丟一次；改次數或定時時間會自動跟著變。
- **工具耐久耗盡**：按完互動鍵後，若遊戲畫面上方跳出「工具耐久耗盡，請使用維修盒」（只比對白色的字形，不受背景影響，模板為 `templates/gather/toolBroken.png`，比對閥值在設定頁「進階 > 採集」），會立刻丟維修盒；沒有勾選丟維修盒、或連丟 3 次仍耗盡，會通知並停止。
- **開始前檢查維修盒**：勾選丟維修盒時，按「開始」後會先打開背包、篩選「維修盒」，只看木頭材質的那種，讀出數量並在日誌顯示「預計可執行到 今天／隔日／X 天後 HH:MM（24 小時制）」（每個維修盒撐一個間隔）。數量是用 `templates/digits` 裡 0～9 的字形圖辨識的（取自背包格子的數量，6 與 8 偶爾可能混淆，所以是「預計」），讀不出來時只會顯示「有維修盒但讀不出數量」，不影響執行。找不到維修盒會跳通知。
- **無工具（植物）沒有維修盒設定**：只有斧頭才需要。
- **倒數圖示**：採完（植物 1 次、木頭 3 次）後，目標會消失並在原地出現倒數圖示（植物是「雲裡一株芽」`templates/gather/respawnPlant.png`，木頭是「斧頭」`respawnWood.png`；每次要採的不一定是同一種，所以兩種都認）。連按途中若看到圖示（例如設 3 次但第 2 次就採完），剩下的次數就不按，避免對著空氣揮。圖示只看遊戲畫面中間偏上的範圍。
- **多久沒採到東西就停止**（預設 10 分鐘，0＝不停止）：採到東西時，畫面會出現兩個跡象——上面的倒數圖示，和畫面上方灰白色的圓角「獲得物品」氣泡（「橘子+1」、「木材+1」…）。**兩個都沒看到**就開始計時，只要任何一個出現就重新計時；連續超過設定的分鐘數都沒看到，就通知並停止（桌面通知，工作列圖示閃爍），可能是離目標太遠、被卡住、沒東西可採或工具壞了。氣泡只認外形（大小、長寬比、圓角、裡面有圖示和字），不看物品名稱，所以不管採什麼都適用。每輪按完會多等幾秒確認。這個分鐘數必須大於定時時間的 2 倍。
- **前景只比對遊戲視窗**：採集的前景模式只截取遊戲視窗的範圍，視窗外的內容不會被誤判（釣魚、料理維持原本的整個螢幕）。

### 浮動日誌

遊戲視窗很大、看不到程式本身的日誌時，按「開始」會在螢幕上跳出一個置頂的小日誌視窗（半透明、只顯示正在執行的那一個任務；前景、背景定時同時跑時會標出 `[前景]`、`[背景]`）。任務結束就自動收起，也可以按右上角的 × 先收起。

- **運行時間**：視窗標題列顯示「運行日誌」與已執行多久（結束後顯示共執行多久）。程式每個任務頁的「運行」標題旁有狀態徽章（未運行 / 運行中 0:12:34），標題下方顯示「上次執行 10/10 11:06　共 1 小時 1 分」，上次執行的紀錄存在 `config.ini`（`lastRun…`），重開程式也還在。
- **位置**（設定分頁「一般設定」，勾選顯示後才出現位置選單）：螢幕四個角落（預設左下角）、自訂。直接拖曳日誌視窗就會記住新位置並切到「自訂」。
- **不影響遊戲**：顯示時不會搶走遊戲的焦點，不會出現在工作列，也不會被截進比對用的畫面裡。
- 不想要的話，到設定分頁取消勾選。

## 注意事項

- 煮料理時，請務必關閉遊戲內「玩法設定 → 開始烹飪鏡頭自動轉動」。
- 料理建議只煮簡單的菜品；時間短的一次煮 1～2 份，最多煮 3 份。
- 以上提醒在各功能頁「運行」旁的「注意事項」按鈕也看得到。
- 雪雕後方的背景越單純越好，背景太雜容易誤判而點錯位置。
- 若「開始烹飪」按鈕呈灰色（食材不足），料理會自動停止。

## 設定

設定分頁的值會寫入 `config.ini`（第一次執行時由預設範本 `config.default.ini` 複製而來，是各人的本機設定，不納入版本控制），也可以直接編輯該檔案。設定分頁最下方的「還原設定值」可重置所有設定，回到最初始狀態；每個設定欄位旁也都有「還原預設值」按鈕，可單獨還原。偵測與點擊頻率預設 0.05 秒。

| 設定 | 說明 |
| --- | --- |

## 打包

```powershell
pyinstaller --noconsole --add-data "config.default.ini;." --add-data "ui;ui" --add-data "templates;templates" --add-data "tools/ADBKeyboard.apk;tools" main.py
```

打包時內建的是預設範本 `config.default.ini`；打包後的 `config.ini` 會放在 exe 旁邊，第一次執行時由範本複製，重新打包不會蓋掉你的設定。

## 自動更新與發佈新版

打包後的程式啟動時會到 GitHub Releases 查詢新版本，有的話在視窗上方提示，按「立即更新」就會自動下載、替換並重新啟動（`config.ini` 不會被覆蓋）。設定分頁也有「檢查更新」按鈕。從原始碼執行只會提示，不會自動替換。

### 事前準備（只需一次）

1. 安裝 [GitHub CLI](https://cli.github.com)。
2. 在終端機執行 `gh auth login`，依指示登入 GitHub。

### 發佈步驟

1. 修改 `version.py` 的 `VERSION`（例如 `1.3.0`），並把這一版的更新內容寫進 `RELEASE_NOTES.md`（每次發佈前直接覆蓋成新內容），commit 並 push 到 GitHub。
2. 在專案資料夾的 PowerShell 執行：

   ```powershell
   .\release.ps1
   ```

3. 腳本會顯示要發佈的版本號，輸入 `y` 確認後，自動完成：打包、壓成 zip、在 GitHub 建立 tag 為 `v1.3.0` 的 Release 並上傳 zip。Release 說明就是 `RELEASE_NOTES.md` 的內容，使用者的更新提示也會顯示它。
4. 使用者開啟程式時就會看到更新提示。

### 只建立草稿（測試用）

```powershell
.\release.ps1 -Draft
```

草稿只有你看得到，不會被更新檢查查到。要測試自動更新本身則必須發佈正式版，測完請到 GitHub 刪除該 Release 與 tag。

### 腳本會擋下的情況

- 找不到 `RELEASE_NOTES.md`，或它與 `version.py` 有尚未 commit 的修改。
- 目前的 commit 還沒 push 到 GitHub。
- 該版本號的 Release 已經存在（請先調高版本號）。
- `gh` 未安裝或尚未登入。

也可以手動發佈：自行打包並壓縮 `dist/main`，到 GitHub 建立 Release、tag 設成 `v` 加版本號，再上傳 zip。

注意：zip 內須含 `main.exe`（可以直接放在最上層，或多包一層資料夾）。
